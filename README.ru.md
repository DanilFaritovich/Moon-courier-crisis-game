**Moon Courier Crisis** — пошаговая игра о лунной логистике с полноценным бэкендом и веб-интерфейсом. Игрок управляет луноходами, выполняет контракты на доставку, учитывает заряд аккумуляторов и грузоподъёмность и следит за ходом миссий через интерфейс центра управления.

Проект создан для портфолио и демонстрирует разработку Python-бэкенда с разделением ответственности между слоями, типизированный фронтенд на Vue, автоматизированное тестирование, развёртывание через Docker и проверки качества кода в CI.

## Что демонстрирует проект

### Разработка бэкенда

- REST API на FastAPI с типизированными моделями запросов и ответов на Pydantic.
- Сервисный слой для игровой логики, луноходов, заказов, доставок, событий и графа маршрутов.
- Репозитории на SQLAlchemy и абстракция Unit of Work для работы с данными.
- Проверка игровых правил на сервере: доступность маршрута, ограничения по грузу, прогноз расхода заряда, жизненный цикл доставки и обработка ходов.
- Разделение API, бизнес-логики, хранения данных и моделей передачи данных.
- Структурированное логирование и эндпоинт проверки состояния сервиса.

### Разработка фронтенда

- Vue 3 и TypeScript с использованием Composition API.
- Интерактивная лунная карта на SVG с перемещением и масштабированием.
- Назначение луноходов с помощью перетаскивания (drag-and-drop).
- Выбор контрактов и подтверждение доставок.
- Типизированный API-клиент и синхронизация состояния интерфейса с ответами бэкенда.
- Тестирование компонентов и пользовательских сценариев с помощью Vitest и Vue Test Utils.
- Сквозные браузерные E2E-тесты на Playwright.

### Развёртывание и контроль качества

- Docker Compose для запуска всего приложения.
- Nginx для раздачи фронтенда и проксирования запросов к FastAPI.
- GitHub Actions CI с проверками бэкенда, фронтенда, Docker-окружения и E2E-сценариев.
- Проверки с помощью Ruff, Mypy, Pytest, ESLint, Prettier, `vue-tsc`, Vitest и сборки фронтенда.

## Архитектура

```text
Интерфейс Vue 3 / TypeScript
            │
            │ HTTP
            ▼
     Роутеры FastAPI
            │
            ▼
        GameService
            │
            ├── RoverService
            ├── OrderService
            ├── DeliveryService
            ├── EventService
            └── GraphService
                    │
                    ▼
       Репозитории SQLAlchemy
                    │
                    ▼
                  SQLite
```

Фронтенд отвечает за отображение состояния и отправку команд. Игровые правила и изменение состояния реализованы на бэкенде: это позволяет хранить бизнес-логику в одном месте и тестировать её независимо от интерфейса.

## Основные технические решения

- **Бэкенд — источник истины.** Клиент не рассчитывает результат доставки самостоятельно: перед подтверждением действия он запрашивает у API доступные контракты и прогнозируемый заряд аккумулятора.
- **Разделение игровой логики на сервисы.** `GameService` координирует работу сервисов луноходов, заказов, доставок, событий и графа, а не размещает все правила в обработчиках HTTP-запросов.
- **Абстракция репозиториев.** Логика хранения данных отделена от бизнес-логики с помощью интерфейсов репозиториев и слоя Unit of Work.
- **Готовая игровая сцена при запуске.** Во время старта приложение инициализирует лунную карту, луноходы и контракты, поэтому игровой процесс можно продемонстрировать сразу после запуска.
- **Автоматизированные регрессионные проверки.** Помимо модульных тестов и тестов компонентов, Playwright проверяет пользовательские сценарии в браузере.
- **Воспроизводимый локальный запуск.** Всё приложение запускается одной командой Docker Compose.

## Запуск приложения

### Через Docker — рекомендуемый способ

**Требования:** Docker Engine или Docker Desktop и Docker Compose.

```bash
git clone https://github.com/DanilFaritovich/Moon-courier-crisis-game.git
cd Moon-courier-crisis-game
docker compose up --build
```

После запуска откройте приложение в браузере:

```text
http://127.0.0.1:8080
```

Nginx раздаёт приложение Vue и проксирует API-запросы в контейнер FastAPI. Остановить приложение можно сочетанием `Ctrl+C`, если Compose запущен в текущем терминале.

## Запуск для разработки

### Бэкенд

**Требование:** Python 3.14.

Из корня репозитория выполните:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt

cd backend
uvicorn app.main:app --reload
```

> Команда `source .venv/bin/activate` приведена для Linux и macOS. В Windows команда активации виртуального окружения отличается.

Адрес бэкенда:

```text
http://127.0.0.1:8000
```

Интерактивная документация FastAPI:

```text
http://127.0.0.1:8000/docs
```

### Фронтенд

**Требования:** Node.js 22 и npm. Для локальной разработки сначала запустите бэкенд, затем в **другом терминале**, из корня репозитория, выполните:

```bash
cd frontend
npm ci
npm run dev
```

Обычно Vite запускает приложение по адресу:

```text
http://127.0.0.1:5173
```

В режиме разработки Vite проксирует запросы `/game` и `/health` к FastAPI на `http://127.0.0.1:8000`.

## Игровой процесс

1. Выберите свободный луноход или перетащите его к пункту назначения на лунной карте.
2. Запросите контракты на доставку, доступные выбранному луноходу.
3. Выберите контракт, который можно выполнить с учётом ограничений.
4. Проверьте груз, вознаграждение и прогноз расхода заряда аккумулятора.
5. Подтвердите доставку.
6. Перейдите к следующему ходу, чтобы обработать активные миссии и получить обновлённое состояние игры.
7. При необходимости отмените активную доставку и верните луноход в исходное состояние.

## Обзор API

| Метод | Эндпоинт | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Проверка состояния сервиса |
| `GET` | `/game/state` | Получение текущего состояния игры |
| `GET` | `/game/map` | Получение точек и дорог лунной карты |
| `GET` | `/game/rovers/{rover_id}/available-orders` | Доступные контракты и прогноз заряда для лунохода |
| `POST` | `/game/deliveries` | Назначение лунохода на заказ |
| `DELETE` | `/game/deliveries/{delivery_id}` | Отмена активной доставки |
| `POST` | `/game/next-turn` | Переход к следующему ходу симуляции |

Эндпоинт `POST /game/initialize` сохранён для совместимости API. Текущий интерфейс не вызывает его: бэкенд создаёт стартовое игровое состояние при запуске.

## Проверки качества и тестирование

### Бэкенд

Запустите команды **из корня репозитория** с активированным виртуальным окружением:

```bash
python -m ruff check .
python -m ruff format --check .
python -m mypy .
python -m pytest
```

### Фронтенд

```bash
cd frontend
npm run format:check
npm run lint
npm run typecheck
npm run test
npm run build
```

Для E2E-тестов требуется установленный браузер Playwright и запущенное приложение. Например, из корня репозитория запустите `docker compose up --build -d`, затем выполните:

```bash
cd frontend
npx playwright install chromium
E2E_BASE_URL=http://127.0.0.1:8080 npm run test:e2e
```

CI дополнительно собирает Docker-образы, запускает приложение, проверяет `/health` на бэкенде, выполняет smoke-тест API через Nginx и запускает Playwright против контейнеризованного приложения.

## Ограничения текущей версии

- В демонстрационной сборке используется SQLite в памяти процесса бэкенда.
- Игровое состояние привязано к одному процессу бэкенда и сбрасывается при его перезапуске.
- Аутентификация и отдельные сохранения для нескольких игроков не входят в первую версию.
